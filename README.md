# CIAN-Editor · ویرایشگر چیدمان «پرونده در یک پوست‌گردو»

صفحه‌ی ویرایشگر چیدمان اتاق‌های بازی Case in a Nutshell. نشانی نهایی:

```
https://luckylion.games/case-in-a-nutshell/editor/
```

## چه کارهایی می‌شود کرد

- **فهرست پرونده‌ها** در ستون چپ: هر پرونده‌ی بازی خودش آنجا می‌آید (لازم نیست کسی چیزی اضافه کند). با کلیک روی پرونده اتاق‌هایش باز می‌شود و روی هر اتاق کلیک کنید. هر پرونده دکمه‌های Preview و Publish دارد.
- **ویرایش در اتاق:** با کلیک شیء را انتخاب کنید، بکشید (به شبکه‌ی ربع‌خانه می‌چسبد، Shift = ریز)، `R` می‌چرخاند، `Delete` برمی‌دارد، کلیدهای جهت‌نما تکان می‌دهند، `Ctrl+Z` و `Ctrl+Y` لغو و بازگشت. اقلام کوچک (فنجان، دفتر) با میزبانشان می‌روند.
- **شیء قفل‌شده** (پازل، قفل، چیزی که نمای نزدیک دارد، چیزی که لحظه‌ای از پرونده عوضش می‌کند): فقط جا و جهتش عوض می‌شود. موتور بازی این را اجرا می‌کند، نه همین صفحه.
- **پنجره، در و قاب به دیوار دیگر:** قلم دیواری را بکشید؛ هر طرف خط وسط اتاق ببرید‌ش به همان دیوار می‌رود (یا در پنل Selected از انتخاب «wall» استفاده کنید). در فایل چیدمان به‌صورت فیلد `to` ذخیره می‌شود. دو قلم روی هم افتاده در بررسی‌ها هشدار می‌دهند.
- **کتابخانه:** همه‌ی ۵۷ شیئی که کد می‌کشد با عکس، همه‌ی نقاش‌های دیوار، و تصویرهای خودتان. «Use» ظاهر شیء انتخاب‌شده را عوض می‌کند، «Add» شیء تازه می‌گذارد، «PNG» عکس را برای ویرایش در برنامه‌ی پیکسل‌آرت می‌دهد.
- **تصویر خودتان:** «Add an image» یا «Replace with my image» عکس را از بررسی پیکسل‌آرت می‌گذراند: تشخیص شبکه‌ی پیکسل (تصویر بزرگ‌شده را به پیکسل واقعی برمی‌گرداند)، شفاف‌کردن پس‌زمینه‌ی تک‌رنگ، بریدن، قفل‌کردن رنگ‌ها روی پالت بازی، و گزارش. چیزی که با سبک بازی نمی‌خواند بی‌صدا وارد کتابخانه نمی‌شود: هشدار می‌دهد و تأیید صریح می‌خواهد.
- **کف، دیوار و رنگ اتاق** (تب Room): نوع کف، سبک هر دیوار، هر رنگ اتاق، یا یک تصویر کاشی‌شونده‌ی خودتان. فرش اتاق سر جایش می‌ماند. اندازه‌ی اتاق (هر ضلع ۴ تا ۱۳ خانه، مجموع حداکثر ۱۷ چون بوم بازی ۱۷۶ پیکسل است): درها و اشیای نیمه‌ی دور با دیوارها می‌آیند.
- **ابزارها:** ساعت روز/شب، لحظه‌های پرونده، تصویر مرجع نیمه‌شفاف زیر اتاق، شبکه و جای پا و شماره‌ها.
- **ذخیره و انتشار:** Save draft (خودکار هم ذخیره می‌شود، در همین مرورگر)، Export file، Preview (بازی با پیش‌نویس)، Play from here (بازی در همین اتاق)، Publish، و نسخه‌های ذخیره‌شده با بازگردانی.
- **بررسی خودکار:** بیرون‌زدگی از اتاق، هم‌پوشانی، جلوی در، قلم کوچک روی میزبان، و همین‌ها در هر لحظه‌ی پرونده.

## آنچه هنوز کامل نیست (صادقانه)

- **Publish** در سایت به سرور می‌فرستد (Worker سایت، `worker/NUTSHELL_EDITOR.md` در مخزن `luckylion-website`)؛ بازیکن‌ها همان لحظه چیدمان منتشرشده را می‌بینند. بدون `editor-config.json` (اجرای محلی) نسخه را در مرورگر ذخیره می‌کند و `layout.json` را دانلود می‌کند.
- در سایت پیش‌نویس‌ها، نسخه‌های منتشرشده و کتابخانه‌ی تصویر روی سرور (D1) نگه داشته می‌شوند و بین مرورگرها مشترک‌اند؛ یک نسخه‌ی کپی در `localStorage` هم می‌ماند تا Preview و «Play from here» کار کنند. بدون سرور همه‌چیز فقط در مرورگر است.
- **ورود:** در سایت ویرایشگر پشت نام کاربری و رمز است (سمت سرور؛ بدون نشست حتی فایل‌هایش داده نمی‌شود). کاربر را با `node scripts/nutshell-editor-user.mjs` در مخزن سایت می‌سازید. نقش‌های جدا (مالک/ویرایشگر) نیست: همه‌ی کاربران یک‌جور دسترسی دارند.
- اتاق بزرگ‌تر از ۱۷ خانه‌ی مجموع (به تغییر بوم کل بازی نیاز دارد)، زمان‌های مختلف (`overrides` هر لحظه) داخل چیدمان، و بررسی «راه بسته» و «سرنخ پشت شیء» هنوز نیست.

## این مخزن چیست

فایل‌های ایستا و بدون مرحله‌ی ساخت:

```
index.html     صفحه
editor.js      منطق صفحه
store.js       پیش‌نویس‌ها، نسخه‌ها، کتابخانه‌ی تصویر (localStorage)
importer.js    بررسی پیکسل‌آرت (توابع خالص؛ در مرورگر و در آزمون node)
library/       (اختیاری) sprites.json: کتابخانه‌ی مشترک
```

موتور و پرونده‌ها را موقع اجرا از پوشه‌ی `../assets/` بازی می‌خواند:

```
../assets/editor-manifest.json   پرونده‌ها، اتاق‌ها، لحظه‌ها، فهرست کتابخانه و هش اسکریپت‌ها (بیلد بازی می‌سازد)
../assets/engine.js              موتور (شامل layout.js و library.js)
../assets/case-<slug>.js         پرونده‌ی انتخاب‌شده، همراه layout.json خودش
```

پس صفحه باید کنار بازی سرو شود: `.../case-in-a-nutshell/editor/index.html` و `.../case-in-a-nutshell/assets/`.
مخزن بازی: `eqbalhozhabr/Case-in-a-Nutshell` (موتور، `layout.json`ها، ابزارها و `docs/LAYOUT.md`).

## پرونده‌ی تازه

پرونده‌ی منتشرشده (در `src/cases/index.json`) بعد از بیلد بازی خودکار اینجا می‌آید. پرونده‌ای که هنوز در حال ساخت است و در `index.json` نیست، فقط در بیلد محلی با `EDITOR_DRAFTS=1` دیده می‌شود (بیلد عمومی هرگز آن را بیرون نمی‌دهد، چون `case.js` پاسخ پرونده را دارد):

```bash
EDITOR_DRAFTS=1 npm run assemble
```

## اجرا و آزمون

```bash
npm run assemble        # بازی را می‌سازد و بازی + ویرایشگر را در out/site/ کنار هم می‌گذارد
npm run serve           # همان را روی http://localhost:8080/editor/ می‌گذارد
npm test                # آزمون importer + آزمون مرورگری (نیاز به playwright)
npm run test:server     # ویرایشگر روی Worker سایت: ورود، ذخیره روی سرور، انتشار، و بازی که چیدمان منتشرشده را می‌گیرد (نیاز: ../luckylion-website یا SITE_REPO)
npm run assemble:site   # مثل assemble، و editor-config.json برای سایت را هم کنار out/editor می‌گذارد
```

مخزن بازی به‌طور پیش‌فرض در `../Case-in-a-Nutshell` جست‌وجو می‌شود؛ مسیر دیگر را با `GAME_DIR` بدهید.

## گذاشتن روی سایت

`npm run assemble` دو خروجی می‌دهد:

```
out/editor/   ویرایشگر به‌تنهایی، با همان چند فایل بازی که لازم دارد (engine.js، case-*.js، editor-manifest.json) در assets/ خودش
out/site/     بازی + ویرایشگر کنار هم (برای آزمون محلی)
```

برای سایت فقط `out/editor/` را به `public/case-in-a-nutshell/editor/` مخزن `luckylion-website` کپی کنید. به هیچ فایل بازی دست نمی‌زند و با بقیه قاطی نمی‌شود. (شاخه‌ی `editor-section` در آن مخزن همین را دارد.) هر بار موتور یا پرونده‌ها عوض شد دوباره `assemble` بزنید و همان پوشه را جایگزین کنید.

نکته: «Preview» و «Play from here» بازی زنده را با پیش‌نویس باز می‌کنند؛ بازی زنده باید با بیلد تازه‌ی مخزن بازی (که `?layout=draft` را می‌فهمد) منتشر شده باشد.
